# AI 레이더

AI 공모전 · 영화제 · 지원사업 · 뉴스 브리핑 · 유튜브 · AI 작품을 한 화면에서 봅니다.

- 사이트: https://kjyart-star.github.io/ai-radar/
- 구성: 정적 사이트 한 장(`index.html`) + 매일 아침 수집하는 GitHub Actions(`.github/workflows/collect.yml`) + 수집 결과(`data/*.json`)

## 자유게시판 설정

자유게시판은 **Firebase**(구글 로그인 + Firestore)로 돌아갑니다.
아래를 마치기 전까지 게시판 메뉴에는 "게시판 준비 중입니다" 안내만 나오고,
**나머지 메뉴는 지금처럼 그대로 동작합니다.**

전부 무료 티어로 충분합니다. **결제 수단을 연결할 필요가 없습니다.**

### 1. 새 Firebase 프로젝트 만들기

https://console.firebase.google.com 에서 **새 프로젝트**를 만듭니다.

> 회사 관리시스템이 쓰는 프로젝트를 재사용하지 마세요.
> 공개 게시판과 사내 데이터가 한 프로젝트에 있으면 규칙을 한 번 잘못 건드렸을 때
> 회사 자료까지 열립니다. 이름은 `ai-radar` 처럼 알아보기 쉬운 것으로 합니다.

Google 애널리틱스는 사용 안 함으로 두어도 됩니다.

### 2. 웹앱 등록하고 config 붙여넣기

프로젝트 개요 화면에서 **웹(`</>`) 아이콘**을 눌러 앱을 등록합니다.
(호스팅 설정은 체크하지 않습니다 — 사이트는 GitHub Pages 에 이미 올라가 있습니다.)

등록하면 아래 같은 값이 나옵니다.

```js
const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "ai-radar-xxxx.firebaseapp.com",
  projectId: "ai-radar-xxxx",
  storageBucket: "ai-radar-xxxx.appspot.com",
  messagingSenderId: "000000000000",
  appId: "1:000000000000:web:abcdef"
};
```

`index.html` 을 열어 **`FB_CONFIG`** 를 찾습니다(파일 위쪽, 자유게시판 설정 주석 바로 아래).
비어 있는 여섯 칸에 위 값을 그대로 채웁니다.

> 이 값들은 **공개되어도 되는 값**입니다. 비밀번호가 아니라 프로젝트 주소에 가깝고,
> 실제 보안은 5번의 보안 규칙이 담당합니다. 저장소가 공개라도 문제가 없습니다.
> (반대로 회사 관리시스템의 접근 키는 이 저장소에 절대 넣지 않습니다.)

### 3. 구글 로그인 켜기

**Authentication → Sign-in method(로그인 방법) → Google → 사용 설정 → 저장**

프로젝트 지원 이메일을 고르라고 하면 대표님 계정을 고르면 됩니다.

### 4. 승인된 도메인 추가

**Authentication → Settings(설정) → Authorized domains(승인된 도메인)** 에서
`kjyart-star.github.io` 를 추가합니다.

이걸 빠뜨리면 로그인 팝업이 뜨자마자 닫힙니다.

### 5. Firestore 만들고 규칙 넣기

**Firestore Database → 데이터베이스 만들기 → 프로덕션 모드**로 시작합니다.
위치는 `asia-northeast3 (서울)` 을 고릅니다.

만들어지면 **규칙(Rules)** 탭으로 가서, 이 저장소의
[`firestore.rules`](./firestore.rules) 내용을 **전부 복사해 붙여넣고 [게시]** 를 누릅니다.

이 규칙이 하는 일:

| | |
| --- | --- |
| 읽기 | 누구나 (로그인 없이 글·답글을 볼 수 있습니다) |
| 글쓰기 | 로그인한 사람만 |
| 수정·삭제 | 본인이 쓴 글만 |
| 좋아요·답글 수 | 로그인한 사람이 한 번에 1씩만 |

### 6. 색인(Index) 만들기 — 글이 안 보이면 여기

게시판 목록은 여러 조건을 한꺼번에 걸어 조회하기 때문에 Firestore 색인이 필요합니다.
색인이 없으면 **브라우저 콘솔에 "The query requires an index" 오류와 함께
바로 만들 수 있는 링크**가 찍힙니다. 그 링크를 눌러 [만들기]를 누르면 끝입니다(1~2분 소요).

미리 만들어 두려면 **Firestore → 색인 → 복합 색인 추가**에서 `posts` 컬렉션에 세 개를 만듭니다.

| 필드 순서 | 쓰는 곳 |
| --- | --- |
| `parentId` 오름차순, `createdAt` 내림차순 | 피드 목록 |
| `parentId` 오름차순, `tags` 배열, `createdAt` 내림차순 | 태그 필터 |
| `rootId` 오름차순, `createdAt` 오름차순 | 스레드 답글 |

### 다 됐는지 확인

사이트에서 **자유게시판** 메뉴를 엽니다.

1. 로그인 없이 피드가 보인다
2. `Google로 시작하기` 로 로그인이 된다
3. 글이 써지고, 내 글에만 수정·삭제 버튼이 보인다
4. 로그아웃(또는 시크릿 창)에서도 그 글과 답글이 보인다

## 마감 알림 구독 (메인 화면)

메인 화면의 마감 목록 바로 아래에서 **메일 주소 하나만** 받아 Firestore
`subscribers` 컬렉션에 적습니다. 로그인은 받지 않습니다.

| 항목 | 값 |
| --- | --- |
| 문서 ID | 메일 주소(소문자) — 같은 사람이 두 번 눌러도 줄이 하나만 생깁니다 |
| 필드 | `email` · `createdAt` · `source`(`"home"`) — 이 셋뿐입니다 |
| 규칙 | `create` 만 허용. `read`·`update`·`delete` 는 **전부 금지** |

위 Firebase 설정(`FB_CONFIG`)을 채우면 자동으로 폼이 나타납니다. **비어 있는 동안에는
폼 대신 메일 링크가 보입니다** — 신청하려던 사람을 놓치지 않기 위해서입니다.
규칙은 `firestore.rules` 의 `subscribers` 블록에 들어 있습니다.

> **명단은 화면에서 볼 수 없습니다.** `read` 를 막아 두었기 때문입니다. 이 한 줄이
> 열리면 누구나 전체 메일 주소를 내려받을 수 있습니다. 명단을 볼 때는 Firebase 콘솔이나
> 관리자 SDK 를 씁니다(규칙을 우회합니다).

### ⚠️ 발송을 붙일 때 지켜야 할 약속

화면에 **"마감 3일 전에 알려드립니다"** 라고 적혀 있습니다. 발송 기능을 만드는 쪽은
반드시 이 기준을 따라야 합니다 — **마감 사흘 전(D-3)에 그날 걸리는 공고를 보냅니다.**
문구를 먼저 걸어 두고 발송이 다르게 나가면 그때부터는 거짓말이 됩니다. 주기를 바꾸려면
`index.html` 의 `HOME_COPY.alertH` 문구를 함께 고칩니다.

수신 거부 방법도 아직 없습니다. 첫 발송 전에 **메일마다 수신 거부 링크**를 넣어야 합니다
(화면에 "언제든 수신을 중단하실 수 있습니다"라고 적어 두었습니다).

### 주소 체계

글 하나하나가 고유 주소를 가집니다.

```
https://kjyart-star.github.io/ai-radar/board/            피드
https://kjyart-star.github.io/ai-radar/board/{슬러그}     글 하나
```

슬러그는 본문 앞부분에서 만든 한글 주소입니다(예: `ai-영상-공모전-후기-7f3a`).
**글을 수정해도 주소는 바뀌지 않습니다** — 이미 공유한 링크가 깨지지 않게 하기 위해서입니다.

GitHub Pages 에는 없는 주소를 앱으로 넘겨 주는 기능이 없어서, 저장소의 `404.html` 이
그 역할을 대신합니다. 이 파일을 지우면 공유 링크로 바로 들어오는 것이 동작하지 않습니다.

### 알아둘 점 — 지금은 안 되는 것

- **글이 검색엔진에 잡히지 않습니다.** 주소는 제대로 생겼지만 실제 파일이 없고
  자바스크립트가 그려 내는 방식이라, 검색엔진 크롤러에게는 빈 페이지로 보입니다.
- **카카오톡·SNS 에 글 링크를 공유해도 미리보기에 글 내용이 뜨지 않습니다.**
  사이트 공통 소개가 대신 뜹니다. 링크 자체는 정상으로 열립니다.
- 이 두 가지가 사람이 모이는 데 가장 큰 병목입니다.

**해결 방법은 이미 길이 나 있습니다.** 글마다 실제 HTML 파일(`board/{슬러그}.html`)을
만들어 두면 됩니다. 그래서 글에 `slug`·`excerpt` 를 저장해 두었고, 주소 체계도 지금부터
경로 방식으로 맞춰 놓았습니다. **나중에 정적 페이지를 만들어도 주소가 바뀌지 않습니다.**
남은 일은 GitHub Actions 가 Firestore 를 읽어 그 파일들을 생성하도록 붙이는 것뿐입니다.

- 대표 이미지는 `assets/og-cover.png`(1200×630)로 연결해 두었습니다.

### 도메인

**`https://ai-radar.kr`** 을 씁니다(2026-08-15 연결). 커스텀 도메인을 붙이면 저장소가
도메인 루트에 서빙되므로 **옛 프로젝트 경로 `/ai-radar/` 는 붙이지 않습니다** — 붙이면 404 입니다.

주소를 또 바꿀 일이 생기면 `index.html` 에서 두 곳만 고칩니다.

| 위치 | 무엇 |
| --- | --- |
| `<head>` 맨 위 블록 | `og:url` · `og:image` · `canonical` (문자열로 적혀 있습니다) |
| `var SITE_URL` | 실행 중에 절대 주소를 만드는 곳(공유 링크)이 씁니다 |

`<head>` 쪽을 스크립트로 만들지 않은 이유는 카카오톡·페이스북·슬랙의 미리보기 수집기가
자바스크립트를 실행하지 않기 때문입니다. JS 로 넣은 `og` 태그는 공유 카드에 잡히지 않습니다.

본문 링크는 `BASE` 가 `location.pathname` 에서 실행 중에 계산하므로 손댈 것이 없습니다.
정적 페이지 생성기(`scripts/`)와 `sitemap.xml` 에도 주소가 들어가므로 함께 확인합니다.
